# v0.4 Twin Dashboard and Mock MES Implementation Plan

**Goal:** Explain the existing synthetic work order with traceability, selected board/station links and validated metrics.

**Architecture:** Pure selectors in `src/domain/analytics.ts` derive KPIs, alarm events and board history from immutable simulation events and snapshots. A separate dashboard consumes selectors; 3D selection uses board instance IDs without making rendering the source of truth.

**Tech Stack:** React, TypeScript, R3F, Vitest, Playwright; local data only.

**Spec:** `docs/PROJECT_PLAN.md`, v0.4.

## Tasks
- [ ] Test fixed event fixtures, zero denominators, time-window boundaries and completed/in-progress board history; implement selectors.
- [ ] Add dashboard with simulated work order, KPI formulas, windowed chart, event-derived alarms and board search; connect board/station selection to scene.
- [ ] Test search, route and progress in browser; run lint, typecheck, unit, build and E2E; document limitations and stop before v0.5.

## Review focus
- No data: rates and averages display unavailable, not invented values.
- A window includes events at both endpoints; WIP remains a current snapshot.
- Completed boards remain searchable, but cannot be highlighted in 3D after leaving the line.
- A searched board's history is derived only from its own event IDs, in order.
- A reset clears selection and all derived run data.
