# W5 Mock MES Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task after explicit user approval. Steps use checkbox (`- [ ]`) syntax for tracking. Do not automatically commit.

**Goal:** 在不连接真实 MES 的前提下，为 W4 远程视图提供可查询的合成工单、固定工艺路线、PCB 身份及按事件顺序排列的检验与过程追溯。

**Architecture:** 在现有 Go backend 内建立只读、内存态 mock MES 适配器（不是新增外部服务），用经过 W3 验证且成功应用的事件原子更新追溯投影；通过同源 REST 提供带 epoch、revision、integrity 的查询。React 远程模式查询这些 API，本地演示与 W4 WebSocket 协议保持不变；重启和事件缺失不能恢复，持久化属于 W6。

**Tech Stack:** Go backend、现有 W2 MQTT 和事件 schema、React/TypeScript/Vite、Vitest、Playwright、Docker Compose。

**Spec:** `docs/W2_W6_ROADMAP.md` §3、§7–10；现状和限制见 `docs/W4_REPORT.md`、`docs/EVENT_CONTRACT.md`。

## Global Constraints

- 数据、工单、检验和路线一律标识 **SIMULATED**；只读，无设备控制、真实 MES、生产凭证。
- 沿用 v1 事件及其 ID：当前模拟器固定 `work-order-1`、`board-1` … `board-100`；身份在 `(runId, id)` 作用域内，不跨 run 合并。
- 路线以 backend 的有序 stations 配置为准；目前仅支持从首站到末站逐站前进，无返工、跳站或额外生产路线；不伪造事件或开始加工时间。
- 唯一原子边界是 `Store.Apply` 的锁：重复事件不重复计数，失败、gap、conflict 不写入追溯；离线导入复用相同路径。
- 事件 sequence 是同时间排序依据；分别保留 `simTimeMs`、`emittedAt`、`ingestedAt`；不把 wall clock 当业务时间。
- API 随结果附 `runId`、`epoch`、`revision`、`integrity`、`reason`、`synthetic: true`；不能将 `complete` 解释为端到端无丢失保证。
- 不新增数据库、持久日志、生产身份认证、真实设备连接或远程业务控制；保持本地演示默认、W4 相机、重连及同源代理可用。

## Review Focus

1. 重复 ID、相同 ID 不同内容及同 sequence 冲突：任务 1 测试仅一次投影且冲突冻结。
2. 板关联未知工单或改绑、非法路线、重复加工/检验：任务 1 测试拒绝且投影不发生部分更新；不支持返工/跳站。
3. 数据缺失、进程重启、失联或相同时间事件：任务 1/2/4 测试顺序、版本和完整性标记，不宣称恢复。
4. 失败检验、未检验、未完工：任务 2/3 测试分类和工单对账；不把检测失败称作物理报废。
5. 异步查询旧 run/旧 epoch 或错误状态：任务 4 测试请求失效、404、网络失败与连接状态，避免展示过期追溯。
