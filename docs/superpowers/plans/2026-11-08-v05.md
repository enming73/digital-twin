# v0.5 Fault Injection and Replay Implementation Plan

**Goal:** Implement deterministic simulated mounter fault propagation, recovery, and event-log replay as specified in `docs/PROJECT_PLAN.md` v0.5.

**Architecture:** The pure simulator freezes remaining processing time while a machine is faulted and emits explicit immutable fault/state events. A pure event reducer reconstructs a snapshot at a virtual timestamp; the browser shows read-only historical state without mutating the live run. Timeline/playback use recorded events and virtual time, not render-frame time.

**Tech Stack:** TypeScript, React, Vitest, Playwright.

## Tasks
- [ ] Test frozen work, capacity-driven upstream blocking/downstream starvation, no board loss and recovery; implement fault transitions.
- [ ] Test event-reducer reconstruction at multiple times, reset and identical KPI results; implement replay from config and ordered events.
- [ ] Add simulated fault controls, read-only replay seek/timeline/playback and browser tests.
- [ ] Document recovery and replay semantics; run lint, typecheck, unit, build and E2E; stop before v0.6.

## Review focus
- Fault during processing freezes the remaining duration, PCB identity and illustrative pose.
- Fault of an idle/blocked machine cannot start or transfer its PCB before recovery.
- Queue capacity and FIFO ownership remain valid throughout extended faults.
- Replay never leaks future events into historical state or KPI calculations; repeated seek is deterministic.
- Fault, clear, reset and live controls cannot mutate a historical replay view.
