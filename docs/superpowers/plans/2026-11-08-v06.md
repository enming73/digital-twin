# v0.6 Blender Assets and Performance Implementation Plan

**Goal:** Author original conceptual printer and mounter Blender assets, export named GLBs, retain procedural fallback and report measured performance.

**Architecture:** A reproducible Blender Python script creates two independent PBR scene files and matching local GLBs. React Three Fiber loads static models with a per-model fallback, while the existing snapshot-driven process assemblies, PCB path and selection remain separate.

**Tech Stack:** Blender 4.2 LTS, glTF 2.0, React Three Fiber, Vitest, Playwright.

**Spec:** `docs/PROJECT_PLAN.md` v0.6.

## Tasks
- [ ] Add tests for Blender files, GLB metadata, named nodes, geometry and maximum size; generate assets with Blender script.
- [ ] Add GLB loading/fallback, retain selection and virtual-time assembly animation; browser tests cover normal and failed load.
- [ ] Capture reproducible available-environment performance and asset budgets; document constraints and run all checks.

## Constraints and review focus
- Models are generic originals; no proprietary geometry or logos.
- Two source `.blend` and two `.glb` files; each GLB must be under 2 MiB.
- Asset loading failure must not disable the production line or simulation controls.
- Existing camera, selection and virtual-time animation remain functional.
- This environment may not represent a physical mid-range desktop; report evidence without overstating performance.
